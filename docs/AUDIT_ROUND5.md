## 5. Τι μένει (ειλικρινές backlog)

1. **Socket.IO με ταυτότητα.** Ο client σήμερα δεν χρησιμοποιεί καθόλου sockets, γιατί τα μηνύματα είναι
   τοπικά ή στο Firestore. Αν ενεργοποιηθούν, το `join_room` πρέπει να ελέγχει ότι ο χρήστης συμμετέχει
   στη συνομιλία μέσω του `server/identity`.
2. **Mock API χωρίς σύνδεση.** Τα `/api/users`, `/api/conversations` και `/api/messages` στο `server.ts`
   είναι δεδομένα δοκιμής (in-memory). Πρέπει να μεταφερθούν στο Firestore με κανόνες, ή να
   απενεργοποιηθούν σε παραγωγή.
3. **Οι tenants είναι in-memory.** Οι αλλαγές branding χάνονται σε επανεκκίνηση. Το επόμενο βήμα είναι
   αποθήκευση στο `server/store` (Firestore σε Cloud Run), όπως έγινε για το outreach.
4. **Σχήματα επικύρωσης** (π.χ. Zod) σε όλα τα write paths. Σήμερα υπάρχουν χειρόγραφοι validators με
   tests (tenants, socket, outreach).
5. **Παρατηρησιμότητα:** πραγματικός πάροχος σφαλμάτων (Sentry) και Web Vitals. Η υποδομή υπάρχει
   (`initErrorTracking` / `initAnalytics`).
6. **Τυπογραφία.** Η κλίμακα του Cursor (σώμα 13px, τίτλοι 13,58/16,77px) συγχωνεύθηκε όπως ζητήθηκε.
   Το WCAG δεν ορίζει ελάχιστο μέγεθος, αλλά για αναγνωσιμότητα σε κινητό αξίζει έλεγχος με
   χρήστες (π.χ. 14–16px για το κείμενο σώματος).
7. **Διάγνωση readiness:** οι απαντήσεις είναι αυτοαξιολόγηση. Σε επόμενο γύρο μπορούν να δεθούν με
   περισσότερα τεκμήρια (συνεντεύξεις πελατών από το Builder, ολοκληρωμένα ορόσημα).
